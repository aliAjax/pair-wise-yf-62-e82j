# 海上搜救联合指挥

源提示词摘要：按海域划设搜索区，协调船艇、直升机、无人机和岸上观察点，记录任务变更、通信与天气影响；离线单位恢复后合并状态，过期位置必须明确提示，并提供低带宽模式。

## 技术栈

Next.js 15、TypeScript、App Router、Mantine、Zustand、TanStack Query、React Hook Form、Zod、next-intl、date-fns、MapLibre。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62027`

## 可用流程

- 搜索区从规划、执行到关闭，支持任务范围变更。
- 船艇、直升机、无人机可调派、转入失联、恢复在线。
- 任务单支持新建议题、分配单位、关闭任务和事件留痕。
- 离线模拟与低带宽模式可切换；本地数据由 Zustand persist 保存。

## 离线补传合并

断链期间，巡视（覆盖率）、位置、任务调派以“补传包”形式缓存，每包带**救援单位、业务序号、观测时刻、接收时刻**。网络恢复后在“离线补传合并”面板按当前有效版本合并：

- **按版本而非到达顺序覆盖**：业务序号更大的包才生效，旧位置不能盖掉新位置；合并为纯函数，对包的处理顺序不敏感、可安全重入。
- **同刻位置冲突**：同一单位同一观测时刻出现两条位置时，较新接收者定当前值，另一条进入“待核对”，由值班员采信或驳回。
- **只留历史的阻塞**：搜索区已关闭、单位已失联、任务单容量不足、旧版本或覆盖率倒退的包不改当前调派，仅留存并标明阻塞原因。
- **失败与重试**：可演练“下次补传失败”，整批失败时原包完整保留为 `failed`；恢复后可单包或整批重试，已生效的任务调派与搜索区覆盖率单调不倒退。
- 任务调派生效前会将单位从其它任务单摘除，修复同一救援单位同时挂在两个搜索区的问题。
- 页面列出：待核对包（含核对操作）、阻塞原因、补传队列/失败重试、当前有效位置（含版本号与过期提示）。

合并逻辑为纯函数 `src/lib/merge.ts`（`mergeBackfill` / `resolveReview`），状态编排在 `src/lib/store.ts`。

### 验证合并规则

```bash
node scripts/run-verify.cjs
```

覆盖版本合并、同刻冲突、关闭区/失联/容量阻塞、覆盖率与调派防倒退、失败保留重试、乱序确定性、人工核对等场景（33 项断言）。
